### 优化 #1:Schema 进程内缓存(A1,00:02–00:26)

**问题**:每次提问 agent 都先调 `get_schema`,而 schema 是静态的;但每次都要读
`sqlite_master`、再对 5 张表各跑一次 `COUNT(*)`。生产 service、评测脚本、MCP server
三个调用方共用同一份 schema,这份重复 IO 纯属浪费;以后做「schema 按需检索」也需要这层缓存。

**改动**

- 新增 `app/schema_cache.py`:有界 LRU(16 条)+ 线程锁;键 = (库文件绝对路径, 请求的表名序列,
  `st_mtime_ns + st_size` 签名)。建库脚本是**整库原子替换**,替换后签名必变,旧条目自然失效
- `app/db.py`:`schema_text()` 改为「查缓存 → 未命中再渲染 → 写回」,渲染抽成
  `_render_schema_text()`(输出与优化前逐字一致);新增 `schema_cache_info()` / `clear_schema_cache()`
- `eval/run_eval.py`:summary 落 `schema_cache_hits/misses` 并打印,「缓存真的命中」成为跑批事实;
  整题重试默认值按交接改为 **10 分钟 × 3 次**
- 新增 `scripts/run_rounds.py`(3 轮驱动,任一轮失败即停止整批)、
  `scripts/bench_schema_cache.py`(冷/热单次调用收益)
- 新增 7 例单测 `tests/test_schema_cache.py`:命中不碰库(用 sqlite3 trace 回调数语句,不靠猜)、
  内容变动即失效、表选择与未知表入键、`:memory:` 不缓存、LRU 有界、并发一致

**为什么放 `db.schema_text` 而不是交接里提的 service / agent**:schema 只有一个出口,
生产、评测、MCP 三条链路都从这里取;挂在 service 上评测就跑不到缓存,验收会变成「测了个寂寞」。

**说明**

- **内容零缺失 ×3**:严格 54/54/54 → 53/52/54,宽松口径 54/54/54 → 54/54/54(均为 54/54)。
  严格口径差的 3 次全部是**形状差异**、不是答错:q35 多返回一行「region 缺失无法归属 2 人」(2 次)、
  q47 用百分比 23.91 代替比率 0.2391(1 次)——内容缺失 0,正是 11-01 定双口径要分开的两类。
- **这些差异与本项改动无关,是模型采样波动**:缓存只改 schema 读取路径(文本逐字不变),
  不动表结构、提示词、判定器。为坐实这点另跑了 3 次 `--only q35,q45` 手工探针(2 题,
  见附录):q35 的「无法归属」行 3 次里出现 1 次;q45 多带 `customer_name` 列是 11-01 就有的老习惯
  (历史 54 次自然/注入跑批里 11 次),2 维度 + 1 数值按契约不出图 → 选型掉到 25/26。
- **延迟**:p50 3610–4106ms → 3788–3865ms,两段区间重叠、无可测变化。单题 3–4s 由 LLM 往返主导,
  schema 读取只占毫秒级——如实写「看不出收益」,不硬凑对比(交接 §5.6)。
- **缓存命中**:优化后每轮 `命中/总 get_schema 次数` = 49/54、53/54、52/54;
  键含「表选择」,模型偶尔用 `get_schema(tables=[...])` 子集问法会各占一个键,故 miss 不恒为 1。
- **单次收益**(`scripts/bench_schema_cache.py`):冷 116µs/次 → 热 8µs/次(14.5×),单次省 108µs;
  折算每轮 54 题只省约 5.8ms ≈ 单题 p50 的 **0.17%**。所以本项价值不在跑分,而在
  ① 去掉每轮 54 次不必要的 DDL/COUNT 查询;② 为「schema 按需检索 / 第二数据集」留出进程内底座。
- **边界**:绕过建库脚本**原地**改库时签名可能不变(缓存读到旧行数),需 `clear_schema_cache()`
  或重启进程;项目里库一律由 `scripts/build_db.py` 原子构建、应用侧只读,该边界已写进
  `notes/pitfalls.md`。
- **回归**:`pytest` 143 → 150 例全绿;冒烟 5/5 无漂移;`--date 2026-11-01` 重生成与已提交的
  11-01 报告**逐字节一致**(证明历史快照与脚本重构都没被动过)。
